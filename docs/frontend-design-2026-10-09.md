# 대시보드 시각 디자인

사용자 요청: frontend-design 스킬을 적용해 기존 대시보드의 시각 품질 개선. 스킬 원본은 `.data/skills/frontend-design/SKILL.md`에 받아 읽었으며 개발은 Codex가 수행한다.

방향: 공장 작업의 승인·감시 화면. 실제 현장 영역이 중심이며 큰 홍보 문구나 가짜 실시간 지표를 추가하지 않는다. 기존 API, 안전 판정, 실행·정지 권한은 유지한다.

- 색상: 배경 `#f2f5fa`, 표면 `#ffffff`, 잉크 `#192d45`, 강조 `#2764e7`, 통과 `#148461`, 정지·차단 `#c44848`.
- 글꼴: Windows의 Segoe UI Variable/Malgun Gothic으로 한글 본문을 선명하게, Bahnschrift로 제품명·측정 숫자의 산업 계기 특성을 표현한다. 외부 폰트 요청 없음.
- 배치: 좁은 화면은 작은 탐색 레일, 작업 설정 / 넓은 현장 / 검증 근거의 3열. 태블릿에서는 근거를 하단으로 이동하고 휴대폰은 단일 열로 배치한다.
- 정보: 측정치는 한 줄의 계기 영역으로 묶고, 실제 작업 계약·모델·입력 조건을 설정 패널에 둔다. 정지는 독립된 빨간 컨트롤로 유지한다. 시뮬레이션 범위는 눈에 보이게 표시한다.
- 상태: 판정·센서·연결 상태를 글자와 색으로 함께 표시한다. 현재 실행과 선택한 과거 기록의 구분을 유지한다.
- 검증: 브라우저에서 기존 이력 선택, 입력 조건 변경, 데스크톱/모바일 레이아웃 및 disabled/focus 상태를 확인한다. 모델 호출이나 새 실행 없이 읽기·표시 동작을 확인한다. node 구문 검사와 관련 API 테스트 및 Luna/max 독립 리뷰를 수행한다.

자기 검토: 기존의 초록 SaaS 카드·작은 대문자 라벨·임의 번호를 줄인다. 현장 화면과 실제 6단계 검증 흐름을 시각적 중심으로 삼아 이 프로젝트의 작업 구조를 드러낸다.

## 확인 기록

- 기존 제어 DOM ID 42개 보존, 신규 표시는 backend-status/verdict 2개.
- JavaScript 구문 검사 통과, tests/test_api.py 6개 통과(기존 upstream 경고 1건).
- 1280px의 3열 폭 250/589/270px, 가로 넘침 없음. 390px·320px에서도 가로 넘침 없음.
- 이미지 전용 모드의 텍스트 숨김, 서버 카메라 표시, 과거 정지 기록의 실행 버튼 비활성 확인.
- 선택한 과거 기록의 단계 통과와 최종 정지를 구분해 표시하며, 현재 현장에는 과거 경로를 표시하지 않음.
- 시각 확인 중 새 모델 호출·명령 실행 없음. 임시 뷰포트 설정 복원.
- 화면 캡처: .data/dashboard-design-desktop.jpg.
- 키보드 건너뛰기 링크: Enter 후 MAIN#workspace에 포커스, 다음 Tab은 SELECT#contract. 본문 포커스 테두리 확인.
- 텍스트·시나리오 라벨의 상단 여백 18px 확인. 기본 508px 화면으로 복원 후 가로 넘침 없음.

## 독립 리뷰

리뷰어 `/root/review_dashboard_design`, 생성 요청 모델 `gpt-6-luna`, 추론 `max`, `fork_turns="none"`. 읽기 전용으로 static의 HTML/CSS/JS와 기존 호출 경로를 수정 전 백업에 비교해 확인했다.

- P2: 건너뛰기 링크의 본문 포커스 누락. main에 tabindex=-1 및 focus-visible 스타일을 추가하고 실제 키보드 이동 확인. 해결.
- P3: 중첩된 첫 라벨의 여백까지 제거하는 선택자. 직접 자식 라벨로 범위를 좁히고 브라우저의 계산된 여백 확인. 해결.
- 최종 재검토: 두 항목 해결, 추가 유효 지적 없음. 수정 이후 JavaScript 구문 검사 재통과.

이 변경은 로컬 프론트엔드에 적용됐다. Pod 배포, 새 모델 평가, Isaac Sim 실행 검증은 이번 화면 변경에 포함하지 않는다.

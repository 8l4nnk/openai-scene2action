# Isaac 정상 작업 검증 — 구현 전 기준

2026-10-09. 사용자는 기존 Isaac 3D 화면 연결과 정상 동작의 시뮬레이터 내 증명을 요구했다. 모델의 PASS, 2D 시뮬레이션, 오래된 영상은 그 증거가 될 수 없다.

## 검증 순서

1. 기존 S05 장면과 Isaac 6.1의 구동 가능 여부를 확인한다. 기존 GPU 호스트 시작 실패와 대체 환경은 별도 기록한다.
2. 정상 작업 계약은 빨간 공과 파란 공을 정해진 구역에 순서대로 운반하는 것으로 한정한다. 사람·칼·스패너 조작은 허용하지 않는다.
3. 입력, 모델 후보 계획, F2 판정, Adapter 명령열, 관측과 F3 판정에 동일한 실행 ID를 부여한다. 2D 승인만으로 Isaac 명령을 승인하지 않는다.
4. Isaac 관절·물체 관측과 영상 프레임에 시뮬레이션 시간 및 수집 시간을 기록한다. 프레임 없는 상태와 오래된 프레임은 연결 실패로 표시한다.
5. 물체가 지정 구역에 놓이고 파지가 해제된 뒤 안정화됐는지 독립 관측으로 판정한다. 컨트롤러의 완료 플래그만으로 성공을 결정하지 않는다.
6. 정상 작업 반복 성공 수/시도 수, 물체 위치 오차, 종료 상태, 지연 시간, 실패 원인을 기록한다. 정지 시 명령 중단 및 승인 재사용 차단은 별도 시험한다.

## 구현 및 보고 원칙

- 현재 연결은 미완료이며 새 Isaac 정상 작업 성공 증거는 아직 없다.
- 기존 공격 재현 실행기나 오래된 성공 보고서를 새 실험의 성공으로 사용하지 않는다.
- 실제 로봇 및 ROS2 하드웨어 연결 없이 전용 시뮬레이터에서만 실행한다. 공개 웹에는 원격 셸·임의 명령·키·원문 데이터·무검증 실행 경로를 제공하지 않는다.
- SA별 위해 방지는 docs/harmful-actions.md의 관측 요구사항에 따라 별도 검증한다. 정상 작업 성공은 SA 전체의 방어 성공을 뜻하지 않는다.
- 기존 코드에서 RGB-D 정상 공 운반 경로를 찾았지만 아직 현재 환경에서 검토·실행하지 않았다.

## 현재 준비 상태

- 기존 Isaac Pod `rl3mcfvouemffx`는 호스트 GPU 부족으로 시작 실패. `xh2u9070nbrk68`는 중지 상태로 유지했다.
- 대체 Pod `t98v7b6lrm0frg` 생성: EU-RO-1, RTX 4090 1개, 공식 `nvcr.io/nvidia/isaac-sim:6.1.0`, 기존 네트워크 볼륨 `vkl35ayv3y`, GPU 시간당 $0.89. SSH/Jupyter 없음.
- 기존 정상 S05 USDA와 Isaac Python 3.12.13 존재 확인. Replicator SDGPipeline/OgnSetPrimPose 그래프가 있어 저장 장면을 무검토 재생하지 않았다.
- 먼저 `isaac/normal_baseline`에서 기존 정상 S05 설정으로 xArm 장면을 재구성하는 제어기 단독 시험을 준비했다. 사람/칼/스패너가 있는 저장 장면 그대로의 연결과 워크벤치 통합은 아직 아니다.
- 실행마다 UUID, 프로세스 종료 상태, 해당 실행 결과를 결합한다. 과거 PASS를 새 실행의 성공으로 표시하지 않는다.
- `isaac/evidence_viewer.py`는 생성한 정상 장면 스냅샷과 최종 영상, 제한된 판정 항목만 제공한다. 제어·셸·원문 입력·키·디렉터리 조회 기능이 없다.
- 배포 전 Luna max 독립 재검토와 로컬 전체 회귀 테스트 진행. 실제 GPU 시험의 성공은 별도 기록해야 한다.

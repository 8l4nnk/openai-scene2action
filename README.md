# K-Scene2Action

**AI 로봇의 입력·작업 계획·실행 명령을 단계별로 검사해, 승인된 작업에서 벗어나는 행동을 실행 전에 걸러내는 다단계 필터 솔루션입니다.**

팀 **또봇**의 Codex 해커톤 Track 1, **AI for Safety & Resilience** 프로젝트입니다. 로봇 공정을 도입하는 제조 공장과 로봇 SI를 초기 고객으로 생각하고 있습니다.

외부 작업 지시나 이미지 때문에 AI의 계획이 바뀌면 사람·설비 안전뿐 아니라 품질과 공정 복구에도 문제가 생깁니다. K-Scene2Action의 핵심은 **정상 작업을 기준으로 입력부터 실행까지 여러 단계에서 걸러내는 필터**입니다. 각 단계의 차단 이유를 기록하고, 실행 중 조건이 바뀌면 정지한 뒤 다시 검증합니다.

현재 결과물은 **로컬 2D 시뮬레이션 프로토타입**입니다. 기본 계획은 합성 재생이며, 실제 로봇 안전 인증이나 Codex AI 런타임부터 Isaac 3D 정상 완료까지의 통합 검증을 완료한 제품은 아닙니다.

## 사이트 시연: 정상 2D 운반 → F1·F2 일괄 검사

[로컬 대시보드](http://127.0.0.1:8765/)에서 사용합니다. 이번 녹화용 격리 서버는 [로컬 녹화 화면](http://127.0.0.1:8766/)입니다. 신규 기능은 로컬에서 먼저 녹화하며, [기존 AWS](https://d17ad0or62kzba.cloudfront.net/)와 배포 버전이 다를 수 있습니다.

**녹화 대상은 사이트의 실제 클릭·2D 이동·판정입니다. 기존 Isaac 운반 영상을 대신 사용하지 않습니다.**

1. 「1. 정상 2D 운반」으로 이동해 아래 정상 케이스 사용법대로 **현장 초기화 → 정상 계획 검증 → 시뮬레이션 실행**을 누릅니다. 빨강·파랑 부품 이동과 최종 「완료」를 확인합니다. Isaac 3D 운반 실증이 아닙니다.
2. 「2. EXECUTE 사례와 차단 분포」에서 **F1·F2 사례 한 번에 검사**를 누릅니다. 저장된 텍스트 183건을 재검사하며 새 API 호출이나 Isaac 명령 전송은 없습니다.
3. **F1에서 중단된 사례**를 누르고 원본 입력·기존 Qwen EXECUTE 응답·F1 BLOCK·F2/F3 미실행을 확인합니다.
4. **F2에서 중단된 사례**를 누르고 F1 PASS → F2 BLOCK → F3 미실행·Isaac 전송 0건을 확인합니다.

| 텍스트 EXECUTE 183건 | 통과 | 차단 | 보류 | 미실행 |
|---|---:|---:|---:|---:|
| F1 기존 Astra 일반 입력 선별 | 4 | 167 | 12 | 0 |
| F2 현재 정상 작업 계약 | 0 | 4 | 0 | 179 |
| F3 실행 허가 | 0 | 0 | 0 | 183 |

최초 차단은 **F1 167건 / F2 4건 / F3 0건**, 별도 보류 **12건**입니다. F1은 과거 gpt-6-astra 일반 정책 판정이고 F2는 현재 계약 검사입니다. **기존 실모델 기록을 결합한 오프라인 재검사**이며 현재 실시간 모델 통합 평가가 아닙니다. 원문 fingerprint로 텍스트270건을 연결했습니다. Astra 이미지 세트와 R23 이미지는 달라 결합하지 않습니다. HOLD는 탐지 성공, SKIP은 통과로 세지 않습니다. 정상 대조군이 없어 정확도·오탐률을 주장하지 않습니다.

일반 「입력·Qwen 판정·사례」 선택기로는 전체334건을 별도로 볼 수 있습니다. 해당 기본 검사는 무결성+현재 계약 검사이며 F1/F2 대표 버튼의 Astra 선별 결합 검사와 표시를 구분합니다. 이미지64건 전체는 「R23 이미지64건 → 전체 판정」으로 선택합니다.

새 공격문을 붙여넣는 곳은 **작업 설정 → TEXT → 텍스트 입력**입니다. 위쪽 원본 입력은 읽기 전용입니다. 합성 계획 재생은 텍스트 내용으로 새 계획을 만들지 않으므로 아래 상세 사용법의 입력 필터 안내를 확인하세요.


## 핵심 기능: 입력부터 실행까지 다단계 필터

서버가 관리하는 정상 작업 계약을 기준으로 **입력의 유효성, 계획의 작업 일치, 실제 명령과 경로, 실행 당시 상태**를 차례로 검사합니다. 앞 단계가 통과해도 다음 단계의 검사를 생략하지 않습니다.

| 필터 | 무엇을 걸러내는가 | 검사 방식 | 결과 |
|---|---|---|---|
| **F1 · 입력과 관측** | 형식이 맞지 않는 입력, 센서 손실, 검사할 수 없는 상태 | 입력 모드·형식과 현재 관측·실행 상태 확인 | 거부 또는 보류 |
| **F2 · 작업 계획** | 승인된 대상·목적지·순서를 벗어난 계획 | 서버의 정상 작업 계약과 후보 계획 전체 대조 | 불일치 계획 차단 |
| **Adapter · 명령 재검사** | 계획을 명령으로 바꾸는 과정의 대상·좌표·단계 불일치 | 계약에서 기대 명령열을 다시 계산해 실제 명령과 비교 | 불일치 명령 차단 |
| **F3 · 경로와 실행 조건** | 장애물·작업 경계와 충돌하는 경로, 변경·만료된 실행 조건 | 전체 2D 이동 구간 검사와 실행 직전 재검증 | 차단 또는 보류 |
| **실행 중 감시** | 실행 이후의 센서 손실, 환경 변화, 유효하지 않은 제어 상태 | 현재 상태와 이동 구간을 계속 확인 | 정지·기존 허가 폐기 |

### 정상 작업을 기준으로 걸러내기

색상 분류에서는 **빨간 공을 빨간 목적지로 옮긴 다음, 파란 공을 파란 목적지로 옮기는 작업**을 서버 계약으로 고정합니다. 대상·목적지·순서가 바뀌거나 추가·누락된 작업이 있으면 F2에서 차단합니다. 계약은 외부 입력이 덮어쓸 수 없습니다.

### 실제 명령까지 다시 확인하기

정상 계획이 만들어져도 Adapter가 전개한 명령을 그대로 신뢰하지 않습니다. 접근·파지·이송·해제의 실제 명령열을 계약과 다시 대조하고, F3에서 전체 이동 경로를 검사합니다. 실행 허가는 계약·명령·관측 상태와 유효기간에 묶어 관리합니다.

### 실행 중 변화에도 대응하기

실행 직전에 한 번 더 검증하고 실행 중에도 상태를 확인합니다. 정지·센서 손실·환경 변경 이후에는 **기존 허가로 자동 재개하지 않으며 새 관측으로 재평가**합니다. 차단·보류·정지의 단계와 이유는 실행 기록에서 확인할 수 있습니다.

현재 구현은 로컬 2D 검증입니다. 상세 도구·알고리즘·위험 행동별 대응과 미구현 범위는 [필터 설계안](docs/필터-설계안-2026-10-09.md)에 정리했습니다.

## 필터 판정 분포

기존 입력 분류 평가 334건의 **차단·보류·통과 분포**입니다.

| 입력 | 전체 | 차단 | 보류 | 통과 |
|---|---:|---:|---:|---:|
| 텍스트 공격 라벨 | 270 | **242건 · 89.63%** | 23건 · 8.52% | 5건 · 1.85% |
| 이미지 | 64 | **25건 · 39.06%** | 30건 · 46.88% | 9건 · 14.06% |
| 전체 | 334 | **267건 · 79.94%** | 53건 · 15.87% | 14건 · 4.19% |

보류는 추가 확인이 필요한 상태이며 차단 성공에 합산하지 않습니다. 위 수치는 입력 분류 결과로, 전체 실행 필터의 방어율이나 물리 공격 성공률은 아닙니다. 이미지 정답과 정상 대조가 없어 정확도·오탐률은 산출하지 않았습니다. 선정 위험 1~7 전체에 대한 검증도 별도로 필요합니다.

## 빠른 시작

Python **3.12 이상**과 [uv](https://docs.astral.sh/uv/)가 필요합니다. 저장소 루트에서 PowerShell로 실행합니다.

```powershell
uv sync --locked

# 외부 모델 입력 필터를 사용하지 않는 로컬 합성 재생
$env:S2A_INPUT_GUARD_MODEL=''
$env:S2A_GEOMETRY_BACKEND='python'
uv run python -m scene2action
```

[로컬 워크벤치](http://127.0.0.1:8765)를 엽니다. 서버는 `127.0.0.1`에 바인딩하며 Ctrl+C로 종료합니다. 기본 실행에 API 키는 필요하지 않습니다. 화면의 계획 공급자는 **합성 계획 재생**을 선택합니다.

이력은 Git에서 제외되는 `.data/runs.sqlite`에 저장됩니다. 키·`.env`·비공개 실행 기록은 커밋하지 않습니다. 사용자가 반입을 승인한 공격 입력과 과거 VLM 응답 사본은 `demo/`에 있습니다.

## 정상 케이스를 직접 실행하는 방법: 2D 데모

화면 위 「3. 직접 텍스트 입력 / 2D 실행」을 누르거나 아래 **작업 설정**까지 내려갑니다. 좁은 화면에서는 작업 현장 아래에 작업 설정이 배치될 수 있습니다.

1. **정상 작업 계약 → 색상 분류**를 선택하고 **현장 초기화**를 누릅니다. 진행 중인 실행이 있다면 먼저 **■ 정지**를 누릅니다.
2. **외부 입력 조건 → TEXT**, **텍스트 입력 → `정상 작업을 순서대로 수행해 주세요.`**로 둡니다.
3. **계획 생성 → 합성 계획 재생 · 사전 정의**, **재생 시나리오 → 정상 계획**을 선택합니다.
4. **계획 검증하기 →**를 누릅니다. **검증 결과 → 최종 판정**이 「실행 준비」가 되는지 확인합니다. 차단·보류이면 해당 단계의 이유를 읽습니다.
5. 준비 후 **30초 이내**에 **시뮬레이션 실행**을 누릅니다. 아래 **2D 작업 현장**에서 `red → bin_red`, 그다음 `blue → bin_blue` 이동을 확인합니다. 위쪽 Isaac 카메라는 이 버튼으로 움직이지 않습니다.
6. **검증 결과 → 최종 판정 「완료」**와 **실행 타임라인**을 확인합니다. 상단 현재 실행 상태가 「실행 없음」으로 돌아가는 것은 완료 이후에도 정상입니다. 성공 여부는 선택한 기록의 최종 판정을 봅니다.
7. **판정·관측 기록 내려받기 ↗**로 JSON을 저장할 수 있습니다. 다시 시연하려면 **현장 초기화 → 계획 검증하기 → 시뮬레이션 실행** 순서로 진행합니다.

두 작업은 접근·파지·이송·해제 총 8개 명령으로 전개됩니다. 이 흐름은 합성 계획을 이용한 2D 검사·실행 데모이며, 텍스트를 읽어 새 계획을 생성하거나 3D 공 운반 성공을 검증하는 흐름은 아닙니다.

### 공격문을 넣는 곳과 검사되는 내용

**작업 설정 → 외부 입력 조건 「TEXT」 → 「텍스트 입력」 칸**에 기존 텍스트를 붙여넣고 **계획 검증하기**를 누릅니다. 입력 한도는 4,000자입니다. 위쪽 사례 패널의 「원본 입력」은 읽기 전용이며 자동으로 이 칸에 복사되지 않습니다.

| 사용 목적 | 조작 | 실제 동작 |
|---|---|---|
| 기존 공격에 Qwen이 EXECUTE를 제안했고 F2가 막는 사례 시연 | 위쪽 「F1·F2 사례 한 번에 검사 → F1/F2에서 중단된 사례」 | 저장된 입력·Qwen 응답을 현재 오프라인 정책으로 검사. 새 API 호출·Isaac 전송 없음 |
| 새로운 텍스트 입력 | 아래 「TEXT → 텍스트 입력 → 계획 검증하기」 | 설정된 입력 필터가 있으면 텍스트를 분류. 합성 계획 자체는 선택한 재생 시나리오로 결정됨 |
| F2 차단을 재현하는 2D 시연 | 「합성 계획 재생 → 목적지 불일치」 또는 「작업 순서 불일치」 | 준비된 계약 위반 계획이 F2에서 차단되고 실행 버튼 비활성화 |
| Adapter 차단 시연 | 「합성 계획 재생 → Adapter 명령 변환 불일치」 | 전개된 명령의 불일치를 별도 재검사에서 차단 |
| F3 경로 차단 시연 | 「현장 초기화 → 장애물 추가 → 정상 계획 → 계획 검증하기」 | 2D 이동 경로와 장애물 충돌을 검사. 판정 이유와 실행 버튼 상태 확인 |
| 기존 이미지 공격 조회 | 위쪽 「R23 이미지 64건 → 사례」 | 저장된 원본 이미지·기존 응답 확인. 새 이미지 업로드 기능은 없음 |

**합성 재생에서 공격문만 바꿔도 후보 계획이 바뀌지는 않습니다.** 따라서 입력 필터가 꺼진 상태에서 「정상 계획」을 선택했다면 문구와 관계없이 정상 합성 계획이 검사됩니다. 이 결과를 공격문의 의미를 이해해 방어한 것으로 설명하지 않습니다.

화면의 **입력 필터 안내**를 먼저 확인하세요. 2026-10-09 이 사용법 작성 시 실행 중인 로컬 서버에는 `openrouter / qwen/qwen3-vl-32b-instruct` 입력 필터가 켜져 있었습니다. 이 설정에서는 **합성 재생이라도 검증 버튼을 누르면 입력이 외부 공급자에게 전송되고 비용이 발생할 수 있습니다.** 외부 호출 없이 재생하려면 위 「빠른 시작」처럼 `S2A_INPUT_GUARD_MODEL=''`로 서버를 시작하고, 화면에 「모델 입력 필터 미사용」이 표시되는지 확인합니다. README 작성으로 실행 중인 설정을 변경하지는 않았습니다.

「OpenAI 실모델 · 별도 설정 필요」는 서버의 별도 API 설정이 필요한 과거 직접 모델 호출 경로입니다. 이번 발표 시연은 **합성 계획 재생과 저장된 Qwen 응답 조회**를 사용하며, 이 메뉴를 Codex 런타임으로 소개하지 않습니다.

IMAGE / IMAGE+TEXT를 아래 작업 설정에서 선택하면 서버의 **2D 합성 관측 이미지**를 사용합니다. 위쪽 R23 파일이나 Isaac 실시간 카메라가 자동으로 계획 생성 입력에 연결되지 않습니다.

### 실행 버튼이 비활성화되거나 보류될 때

- 「실행 준비」가 아닌 경우: **검증 결과**에서 차단·보류 사유를 확인합니다. 차단된 기록에는 실행 버튼이 활성화되지 않습니다.
- 승인 후 30초 경과, 장애물·센서·계약 변경, 정지·재시작 이후: 이전 승인을 재사용할 수 없습니다. **현장 초기화 → 다시 계획 검증하기**를 수행합니다.
- 「센서 수신 중단」: **센서 복구** 또는 **현장 초기화** 후 다시 검증합니다.
- 모델 입력 필터에서 오류·거절·보류: 합성 계획의 정상 여부와 별개입니다. 발표용 외부 호출 없는 데모는 「빠른 시작」 설정을 사용합니다.
- 「서버 연결 끊김」: 로컬 서버 프로세스 또는 AWS 로그인 상태를 확인하고 페이지를 새로고침합니다.

## 위험 행동 범위

발표에서는 위험 행동을 1~7로 부르고, 원래 SA ID는 증거 추적을 위해 보존합니다.

| 발표 번호 | 원래 ID | 위험 행동 |
|---|---|---|
| 1 | SA02 | 사람을 잡거나 끌어당김 |
| 2 | SA04 | 칼을 휘두르거나 밀어냄 |
| 3 | SA08 | 스패너로 다른 위험 물체를 활성화 |
| 4 | SA13 | 공을 과도하게 압착하거나 튀어나가게 함 |
| 5 | SA14 | 운반 중 공을 놓쳐 떨어뜨림 |

## Codex 활용과 AI 의존 방침

구현, 문서 작성, 검증, 코드 리뷰는 **Codex만 사용**합니다. 다른 AI 코딩 도구나 에이전트에 작업을 맡기지 않습니다. 필터 개발 코드 변경은 Codex 내부의 독립 `gpt-6-luna` / `max` 리뷰를 거칩니다. 필터 외 코드 변경의 독립 리뷰는 현재 세션 설정을 사용합니다. 적용 범위는 [AGENTS.md](AGENTS.md)에 있습니다.

사용자는 제품의 AI 의존도 Codex로 한정했습니다. 저장소에는 과거 직접 모델 API 계획 생성·입력 필터 코드가 남아 있으나, 이를 Codex 런타임으로 소개하지 않습니다. **Codex AI 실행 연동 및 그 종단 검증은 아직 완료되지 않았습니다.** 현재 실행 안내는 외부 모델 호출 없는 로컬 데모를 기준으로 합니다.

기존 모델 시험은 참고 실험이며 현재 제품의 통합 방어 성능과 구분합니다. 이 README 수정으로 과거 API 코드나 실행 설정을 제거·전환한 것은 아닙니다.

## 개발 검증

개발 환경에서 검증하려면 다음 명령을 사용합니다. 새로운 API 평가나 로봇 실행은 포함하지 않습니다.

```powershell
$env:S2A_INPUT_GUARD_MODEL=''
$env:S2A_GEOMETRY_BACKEND='python'
uv run pytest -q
node --check scene2action/static/app.js
uv run python -m scene2action.benchmark --samples 30
```

Node.js는 위 JavaScript 문법 검사에 필요하며 기본 Python 워크벤치 실행에는 필요하지 않습니다. 임시 폴더 권한 문제가 있으면 pytest에 `--basetemp=.data/test-run-<새 식별자>`를 추가합니다. 벤치마크는 합성 입력의 처리시간이며 SLA나 실제 정지시간을 입증하지 않습니다.

## 선택: C++ 기하 검사

기본 backend는 Python입니다. 이미 설치된 C++17 호환 clang++/g++로 빌드한 뒤 명시적으로 native를 선택할 수 있습니다.

```powershell
uv run python scripts/build_native.py
$env:S2A_INPUT_GUARD_MODEL=''
$env:S2A_GEOMETRY_BACKEND='native'
uv run python -m scene2action
```

라이브러리는 `.data/native/`에 생성됩니다. native를 선택했는데 라이브러리가 없거나 ABI가 맞지 않으면 시작에 실패하며 자동 대체하지 않습니다. Linux Pod에서는 Linux용으로 다시 빌드해야 합니다. 자세한 옵션과 필수 native 테스트는 [native/README.md](native/README.md)를 참고하세요.

## Isaac Sim 연결과 현재 한계

Isaac 장면·에셋 이관, 버전 확인, 정상 동작 시험 및 읽기 전용 증거 뷰어를 위한 코드와 준비 기록이 있습니다. **환경 READY, 장면 렌더, 과거 정상 영상은 현재 필터와 3D 실행의 통합 성공 증거가 아닙니다.** 준비 내용은 [Isaac 이관 기록](docs/isaac-migration-2026-10-09.md), 정상 완료 판정 기준은 [Isaac 정상 작업 검증](docs/isaac-normal-validation.md)에 있습니다.

- 현재 F3는 정규화된 0~1 좌표의 2D 원형 운반체와 AABB 장애물 검사입니다. 반경 0.045는 미터 단위의 안전 거리가 아닙니다.
- 3D 로봇 링크·관절 제한·힘/토크·실제 사람 감지·파지 유지·낙하·물리 제동은 별도 구현과 검증이 필요합니다.
- 입력 이미지는 서버 소유 합성 관측입니다. 현장 카메라·OCR 통합은 미완료입니다.
- 감시 스레드는 Python 프로세스 내부에서 동작합니다. 독립 하드웨어 비상 정지나 고장 시 안전을 보장하는 제어기로 인증되지 않았습니다.
- SQLite 이력은 변경 불가능한 감사 저장소가 아닙니다. 운영 환경의 접근 권한·보관·삭제 정책은 추가로 필요합니다.
- AWS는 로그인 gateway를 거쳐 워크벤치를 제공하며, Pod 카메라는 읽기 전용 프록시로 표시합니다. 배포 확인 시점과 미완료 범위는 [대시보드 검증 기록](docs/demo-dashboard-validation-2026-10-09.md)을 참고하세요. 링크의 지속 가용성이나 3D 통합 완료를 보장하지 않습니다.

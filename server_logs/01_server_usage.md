## 누락과 대체 증빙

- 현재 Runpod API에서 접속 정보를 재확인했으나 기존 SSH 키 인증이 `Permission denied (publickey,password)`로 실패함.
- 컨테이너·시스템 로그 API도 시간 초과로 2회 수집 실패함.
- 권한 확대, 키 등록 변경, 서버 재시작, 로깅 설정 변경을 수행하지 않음.
- 03에는 수집 실패와 확보 범위를 기재. 성공 인증 줄을 확보하지 못했으므로 04는 헤더만 유지. 접속 0건이라는 뜻이 아님.
- 대체 증빙: Codex 로그 ZIP에 오늘 RunPod 대화·도구 실행 결과와 클라이언트 SSH/SCP 수행 메타데이터를 포함. 이는 sshd 인증 로그나 출발 IP의 대체 판정 근거가 아님.
- 다음 확인 필요: 관리자 또는 승인된 Runpod 감사 기록에서 해당 기간·팀 범위 인증/콘솔 접속 자료 확보, 참가자 ID 및 계정·키 공유 범위 확인.

- Drive 업로드는 공유 폴더 보관이며 GitHub 제출 완료를 의미하지 않음.
